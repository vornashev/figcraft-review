# FigCraft Agent (sidecar)

A chat with a coding agent beside FigCraft, like pen.dev's agent panel: Claude Code, Codex or pi through their own CLI and your subscriptions, one history per design file. The plan is in `design/review-ux.figcraft` (page «Агент»).

`sidecar/figcraft-agent` (`figcraft-agent.cmd` on Windows; both run `launch.py`) starts the server if needed and opens the chat at `http://figcraft-agent.localhost:7980`. It opens as an app window of a Chromium-family browser (Chromium, Chrome, Edge, Brave), otherwise in the default browser. On Hyprland it moves the window (class `chrome-figcraft-agent.localhost__-Default`) to FigCraft's workspace. Bind it to a key: [docs/hotkeys.md](../docs/hotkeys.md). `--server` only starts the server.

FigCraft must run with its control channel: `figcraft --control 7979`. `control.py` speaks that channel directly (`FIGCRAFT_PORT`, 7979 by default) for the designer's own comment actions and the app's event log. The launcher restarts a server it started whose code has changed since, unless an agent is working in it. The log is `server.log` in the state folder (see **Chats per file**).

## Chat

- **Header.** The file on a quiet first line, the chat on the second; the whole width up to **+** opens the file's remarks and chats. A chat's ⋯ renames it, copies it as Markdown or deletes it — the deletion waits while the toast's **Вернуть** is on screen.
- **While the agent works.** Enter and the round button queue a message for after the answer; **Остановить** above the input stops the agent, and so does Esc pressed twice. A turn that broke or ran out of the subscription's limit ends with a card: what was done, **Продолжить с шага N**, and for a limit **Другая модель…**.
- **Context.** The chat follows the active FigCraft document and its selection. The selection shows as a dashed suggestion above the input; **Tab** or a click puts it into the text at the caret as chips (`# Heading`), which Backspace deletes and ← → step over like one character. **@** searches the layers of the current page and the remarks by name or `#N`. Pasted, dropped or selected images appear as numbered 56×56 previews above the input, with a remove button and upload progress; their inline chips let the prompt refer to them. Sent images appear as 112×84 previews. Clicking a preview opens a gallery with dimensions, download, arrow-key navigation, zoom (buttons or wheel), fit and a thumbnail strip; Esc closes it. The agent reads layer chips as `«name» (#ID)` plus a `figcraft #ID TYPE «name» W×H — path` line, remark chips as the remark's export, images as file paths (Codex also gets them with `-i`). **+ ▸ PNG слоёв** adds a screenshot of each layer chip's context.
- **First turn** of a chat also gets the file's design system: variables with their values (in the first mode), text styles with their font, size and line height, paint and effect styles, components with their ids and properties — so the agent uses them without looking each one up.
- **Design skills** (`skills.py`): folders with a `SKILL.md` from the project (`<repo>/.figcraft/skills`), yours (`~/.config/figcraft-agent/skills`), the built-in ones (`skills/skills`: better-*, design systems, TypeUI, tweakcn, UI UX Pro Max, and Hallmark: its 50 themes as `hallmark-*` styles and `hallmark` for landing pages, made by `skills/hallmark.py` from a Hallmark checkout) and pen.dev's (`~/.pencil/skills`); the same name in an earlier one wins, and a new folder shows up within seconds. A skill's `metadata` in its frontmatter gives its group (`base`, `style`, `system`, `library` — a kit of ready components, `platform`, `quality`, `task`; else «Другие»), `mode` (`always`, `auto`, `manual`; without one `auto`, pen.dev's `manual`), `title`, `summary` and a `preview` (`"#hex #hex · Font"`). A turn uses the `always` ones, the chat's pinned ones and the message's own: **/** in the input lists them by group (a big group initially shows five; scrolling down or moving below the fifth with ↓ reveals the rest without clicking «ещё»; three letters also search the description; type filters stay selected while typing, and available local thumbnails show in the results), **Space** ticks several (multiple styles and themes; one design system: a second replaces the first), **Tab / Shift+Tab** cycle design types (websites, apps, dashboards, slides, graphics, themes, general); **Ctrl+Enter** (⌘Enter on macOS) or the pin button pins the current skill in the chat; the row **Скиллы чата** above the input opens the pinned ones, the switch for «auto» skills and **Для новых чатов файла**. Chosen skills go into the prompt as their `SKILL.md`, once per agent session; the `auto` ones as a list of paths the agent opens itself. Every agent gets them the same way. The answer's **Скиллы** row names each one and why: всегда, чат, сообщение, or сам (the agent read its `SKILL.md`).
- **Agent and model.** The picker uses agent tabs, model search and descriptions, and marks the current model; under the models it sets the agent's access for all chats, and its foot opens **Настройки** (also Ctrl+, on Linux/Windows, ⌘, on macOS): agents, access, skills and the file's chats. From the input or model button, **Tab** cycles available agents (Claude / Codex / pi) and **Shift+Tab** goes back, remembering each agent's selected model; selected layers and @ or / menus take priority. Hovering or focusing the model button shows its full name, agent, description and shortcuts. Inside the picker, Tab/Shift+Tab switch agent tabs, arrow keys move through that agent's models, Enter confirms, and Esc closes it. The list comes from the available agents; Ctrl/Command shortcuts use physical keys regardless of the keyboard layout.
- **Skill library** (Settings → **Все скиллы**, also from **+**, **/** and the pinned-skills menu): the full catalog with search, group filters and persistent **Всегда / Сам / Вручную** modes. Left/right arrows switch cards in the current search and group. A card shows a style palette, description, actual files and SKILL.md, and can pin the skill in this chat or open its folder. **?** explains levels and sources. **Добавить** copies a local folder with SKILL.md into personal skills without overwriting an existing folder. pen.dev is read-only; new folders appear automatically.
- **Skill references.** Hallmark's 50 style cards include local desktop and phone screenshots, a click to enlarge them in the image gallery, and links to the live example and theme source. `skills/hallmark.py` copies these from the upstream checkout when refreshing the themes (or uses its theme JPG when only the skill folder is available). Any skill can supply a `references.json` beside SKILL.md: `{"images":[{"file":"preview.webp","label":"Десктоп"}],"links":[{"label":"Открыть пример","url":"https://example.org/"}]}`. Only listed raster images inside that skill's folder are served; skills without references keep their palette preview.
- **Skill display.** The quick skill menu has larger list previews and a persistent **Список / Сетка / Просмотр** switch. Grid cards show a large reference above the name and description, keep checkboxes and favorites, and omit the image area for skills without a reference. **←/→** move between cards; **↑/↓** follow the visual rows using the actual layout, including responsive column changes and partial rows. **Просмотр** keeps a compact list beside the large active reference (above the list in narrow panels). Skills without an image show their description and actions immediately, with no empty media block. Clicking a row or pressing **↑/↓** browses without selecting; separate checkboxes and the preview action toggle a skill. The same display works in the chat-pinning menu.
- **Compact source filter (A).** The quick `/` menu places **Источники · Все 7 / 2/7 / 0/7** beside the display modes, with the same control in the full library. Clicking opens a viewport-clamped popup containing independent source checkboxes, counts, **Все**, **Ни одного**, and **Готово**. Changes apply and persist immediately in `figcraft.skillSources`; Escape closes only the popup and restores the editor/search caret, and clicking outside dismisses it. **Alt+←/→** opens the popup from the editor/search; arrows navigate checkboxes and **Space/Enter** toggle them. **Tab** still changes types from the editor. Source choices compose with type, search, Recent/Favorites and all displays, carry into the full library, and survive reload. The old single-source preference is migrated; `null` enables all sources including future installations, while `[]` disables all.
- **Recent and favorite skills.** The quick `/` menu and full library include **Недавние** and **Избранное**. Stars save a favorite without attaching or pinning it; recent history records accepted message selections and newly pinned skills, with up to 20 recent names. These preferences are saved in this browser’s local storage and survive reloads. Missing skills are omitted from these views without deleting saved preferences.
- **Design systems.** **Дизайн-системы** is a separate design type in `/` and the full catalog, with counted filters for **Дизайн-системы / UI-киты / Компоненты и блоки**. Collections (All/Recent/Favorites) sit on their own row above design types. Seven complete local skills cover Material 3, Fluent 2, Carbon, Gravity UI, Material UI, shadcn/ui and Figma Simple Design System. Each bundles pinned native light/dark tokens, foundation tables, component recipes, retained upstream source and licenses, fonts and two locally rendered WebP previews. Agents follow these local specifications to create editable variables, styles and component variants. A card offers **В сообщение** for one turn and **Закрепить в чате** for later turns; adding from the card preserves the draft, prevents duplicates and replaces only a previous message skill in an exclusive group. Rebuild specimens offline with `python3 skills/design_system_previews.py --manifest /tmp/design-systems-render.json` then `node skills/render_collection_previews.mjs /tmp/design-systems-render.json`. `python3 -m unittest sidecar/test_design_systems.py` checks real bundles, provenance and prompt delivery at both levels. Existing TypeUI/UI UX Pro Max visual interpretations stay in Themes. Optional metadata `resource_kind` (`system`, `ui-kit`, `components`), `formats` (space-separated `figma code`), `resource_source` (`official`, `community`, `mixed`) and `access` (`free`, `paid`, `mixed`) supply filters and resource badges. Source badges describe the linked materials, not authorship of the adapter. Kind filters combine with sources and search, carry into the full catalog and survive card navigation; changing the design type resets kind and group filters.
- **Collections and design types.** Skills retain their installation source (`builtin`, project, personal, pen.dev) and independently declare `metadata.origin` (`hallmark`, `opendesign`, or another collection). The library displays collection badges and local thumbnails, filters by source collection and `metadata.category`, and preserves these filters while moving between cards. OpenDesign's 230 public prompt bundles become task skills when you import them: their original prompt, full-size reference image, original bundle instructions, provenance and a FigCraft adapter. They aren't licensed for redistribution, so the repository carries only the importer, and the skills go to your own folder. Types are websites, apps, dashboards, slides and graphics; Hallmark style skills use `themes`. Search also matches collection, localized type and `metadata.style`. Import or refresh them with **Скачать** / **Обновить** beside OpenDesign in the **Источники** popup (the server runs the importer and shows its progress), or with `python3 skills/opendesign.py` (into `~/.config/figcraft-agent/skills`; `--out DIR`, `--cache DIR`, optionally `--index saved-catalog.html`). Cached downloads make retries resumable. `python3 -m unittest sidecar/test_opendesign.py` checks the importer without network access.
- **TypeUI / tweakcn / UI UX Pro Max.** 188 additional manual style skills: `typeui-*` (67), `tweakcn-*` (42), and `uipro-*` (79 active or supplemental styles; deprecated entries are excluded). Each bundle includes source specifications, license, commit attribution, local preview images and links. TypeUI uses the original example images compressed to WebP; tweakcn has light/dark specimens rendered from its semantic tokens; UI UX Pro Max has illustrative specimens based on its style specifications. Specimens are labeled accordingly and are not screenshots from upstream. All three sources appear in the library source filter and can be searched by `typeui`, `tweakcn`, or `uipro` in the quick picker. Rebuild from pinned revisions with `python3 skills/design_collections.py --cache /tmp/figcraft-design-import --fetch`, then `node skills/render_collection_previews.mjs /tmp/figcraft-design-import/render-manifest.json`. Requires ImageMagick, Chromium, and the frontend npm dependencies (for the TypeScript data parser); remote source code is parsed as literals, not executed. The lock file is `skills/collections.lock.json`. `python3 -m unittest sidecar/test_design_collections.py` checks bundle integrity and importer transformations.
- **Answers stream in.** Tool calls fold into steps. When an answer changed the document, a bar says how many undo steps it made: **Показать** brings the file to the front and zooms to the layers it touched, **Отменить** undoes the steps in the agent's own history (yours stays as it is), while they are still its newest. Under a finished answer, **Работал 6 мин 20 с · $2.77** opens what the turn took: cost, input and output tokens, cache reads and writes, the context of its last request against the model's window, and how many requests went to the model (Claude gives all of them; Codex and pi their tokens). It also shows how long the turn took to prepare (its headless FigCraft, the prompt) and to the agent's first output; the server log has a `turn …` line with the same phases. Open or closed, every answer follows the last choice.
- **Access** (model menu or settings): *Только FigCraft* — the agent changes the design and reads project files, but can't run commands or edit files (Claude `--permission-mode default --allowedTools mcp__figcraft Read Glob Grep`, with only those tools and Bash, Edit, Write defined (`--tools`, so figcraft's aren't deferred behind ToolSearch) and `--disable-slash-commands`, Codex `-s read-only`, pi `--tools read,grep,find,ls,mcp`); *Как в терминале* — the agent's own permission settings. When Claude is refused a tool, the answer offers **Разрешить и продолжить**, which allows it for that chat and resumes the session.
- **Chats per file** in `chats/<hash of the path>.json` in the state folder (`$XDG_STATE_HOME/figcraft-agent` on Linux, `~/Library/Application Support/figcraft-agent` on macOS, `%LOCALAPPDATA%\figcraft-agent` on Windows), the last 300 messages each; a chat resumes the agent's session (`claude --resume`, `codex exec resume`, `pi --session`). Switching agents in a chat starts a new session for that agent.
- **Several files at once, FigCraft out of sight.** Each file an agent works in gets its own headless FigCraft: the app hosts the file in a live session on this machine (`collab.host`, done once per file: the app switches to it for a moment, opening it if needed) and the headless one joins it (`guests.py`). The agent's MCP server is `bridge.py`, which hands every request to that file's FigCraft through the chat server. So agents in different files run in parallel, their edits show in the app at once (with the agent's cursor), and it doesn't matter which tab, window or workspace is in front. One turn per file at a time. A turn longer than 20 s ends with a desktop notification. A headless FigCraft idle for 20 minutes is closed; closing the file's tab ends its session, and the next turn starts a new one.
- **Variants (×N)** by the model: an orchestrator (its own agent and model) picks N directions from the style library — the agent's `styles` tool lists every `style`, `system` and `library` skill of every source — and calls `variants`: the chat puts N frames in a row right of the page's content (or copies of a frame the message points at, `base`) as one undo step and runs a lane per frame, each its own CLI, model and guest in the file's live session, so its own cursor «Вариант k · агент» and undo. The menu sets how many, what they differ in (стиль: no style twice, not three from one source; структура: one system, other layouts; адаптив: a width per frame), the orchestrator, each lane's agent, model and pinned style, a time limit per lane (the CLIs report cost only at the end, so money can't be a limit) and presets. When the lanes are done the orchestrator compares them. Then: **Доработать** sends the next message into a lane (its session, frame and cursor; the orchestrator does the same with `lane`), **Повторить** runs a broken one again by any agent, **Беру этот** removes the run's other frames with their «V k ·» collections and «V k/» styles and gives the winner's tokens to the file — one undo step, **Отменить** under the run puts it back — and the winner goes on with **Перенести на экраны** or **Адаптив**; **Смешать…** drafts a message for a new one-direction run, **Сравнить снова** compares again. Under the run: its wall time and cost. Lane numbers go on across a chat's runs, so «V k» never clashes.

## Замечания

The tab shows the document's remarks (`agent/review.py`'s annotations), with a badge for those that wait for you:

- **Ждут тебя** — the agent's questions with their options (keys **1**, **2**…) or a field for your own answer; remarks the agent marked done («Проверь») with «было» (taken when the remark was first seen open) and «стало» (taken when the agent handed it back): **Принять** (Enter or A) or **Вернуть** (R) with a comment. ↑ ↓ move between cards; the footer shows the keys of the selected card; Esc goes back to the chat.
- **У агента** — the open remarks; **Отдать агенту · N** sends them to the chat.
- **Принято** — accepted and rejected ones.
- **Комментарии FigCraft** — the file's open comment threads (FigCraft 0.13), those the agent answered first. **Исправить** hands a thread to the agent, which fixes it and replies in the thread under its own name («Claude (agent)»: the guest's MCP client name) but leaves it open; **Решить** resolves it, **Ответить** replies, **Показать** opens it on the canvas. Your replies and resolves go over the control channel (`control.py`), since everything sent over MCP is signed as an agent. **Отдать агенту** and «Пройти по замечаниям» bring the threads no agent has answered yet, and the tab reloads on the app's comment events (`events.poll`).
- The field at the top adds a remark to the selected layers.

With FigCraft 0.13 the server reads the active file's path from `inspect_document` (an agent's `doc.list` names no paths), pins its own remark calls to the file the window shows (`document`), so a tab clicked meanwhile doesn't take them, and builds the @ index from names and types only (`fields`). An agent allowed to run commands gets `FIGCRAFT_DOCUMENT` and `FIGCRAFT_AGENT`, so its `review.py` acts on the chat's file and signs as it. The first turn lists colours calculated from other variables as `= color/bg × 40%` or `= mix(a, b, 0.3)`.

Agents mark remarks by ending the answer with lines `✓ #N what changed` or `? #N question | option | option`; the server applies them to that file as `review.py` would (Codex's sandbox has no network and pi has no shell in «Только FigCraft»), and the answer says «Отметил: #N → Проверь».

The tab, the selection suggestion and @ work on the app itself, which answers only while it gets frames: on Hyprland a window on a workspace that isn't shown gets none unless a window rule keeps drawing it (see [docs/hotkeys.md](../docs/hotkeys.md)).

```sh
npm --prefix sidecar/web install && npm --prefix sidecar/web run build   # the chat page (figcraft-agent rebuilds it when web/src changes)
npm --prefix sidecar/web run dev                                 # the page with hot reload on :5173, /api proxied to :7980
python3 sidecar/server.py [--port 7980]                         # the server alone
python3 -m unittest discover -s sidecar -p 'test_*.py'          # agents' JSON lines, chats, turns, storage, skills
npm --prefix sidecar/web test                                    # the page's pure helpers (Vitest)
node sidecar/test_ui.mjs [shot.png]                              # the built page in headless Chromium, server stubbed
```

Files: `agents.py` (finding the CLIs, models, the command for a turn, parsing each one's JSON lines into text, deltas, steps and denials), `server.py` (document watching, chats, turns, changes and undo, @ search, remarks, SSE to the window), `guests.py` (a headless FigCraft per file in the app's live session), `bridge.py` (the agents' MCP server; it hands FigCraft's JSON answers on one line, layer trees without null and empty fields, since the agent rereads them every step, and adds **build**: a nested tree of layers with `"$variable"` bindings, `textStyle` and `component` by name, run as one batch — a third of the characters an agent would write as node.create, variable.bind and style.apply steps), `web/` (the chat: React + TypeScript, built by Vite into one `web/dist/index.html` that the server sends; `src/store.ts` holds the page's state, `src/composer.ts` the input with its inline chips, `src/actions.ts` what the page does, `src/components/` the screens; text is Golos Text and JetBrains Mono, bundled from @fontsource, icons Material Design Icons as SVG by name in `src/lib/icons.ts`, the same ones as «Strict · Иконки» in the design file), `launch.py` (the launcher; `figcraft-agent` and `figcraft-agent.cmd` run it).
